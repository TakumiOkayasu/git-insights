# 操作の契約とTypeScriptの型による設計見直し

[interface-first-design](https://github.com/TakumiOkayasu/dotfiles/blob/main/common/skills/interface-first-design/SKILL.md) に沿い、まず「履歴で選んだ変更の差分を開く」という現在のユースケースに絞った。

## 言語に依存しない契約

- Given: 現在の履歴に含まれるコミットと変更ファイルを選択済み。
- When: 選択した変更に「比較を開く」と依頼する。
- Then: 親と選択コミットの内容を比較表示する。追加・削除・名前変更・最初のコミットを扱い、マージは第1親との比較とする。
- Failure: 内容取得に失敗したら表示せず、呼び出し側へ失敗を返す。取得中に選択の世代が変わったら古い比較は表示しない。不正な画面要求や現在の履歴に存在しない選択は実行しない。

役割は「履歴の選択受付」「選択済みの比較」「内容取得」「比較表示」。中心となる最小契約は、選択済みの比較に対する `open(): Promise<void>` の1操作。履歴は比較の内部状態を問い合わせて処理を組み立てない。

## 協調と生成境界

1. 履歴の受付が外部メッセージを検証し、現在のコミットと変更一覧に選択が実在するか確認する。
2. Git側の生成境界が、コミット・変更のデータから選択済みの比較を生成する。
3. 履歴は比較の `open()` を呼ぶ。
4. 比較は必要な版の内容を取得し、まだ現在の選択であれば表示役へ渡す。

`comparison.ts` は操作契約のみ。`git-comparison.ts` はGitの表現を解釈する生成境界で、追加・削除・旧パス・第1親の判断を閉じ込める。`vscode-comparison.ts` はVS CodeのURIや差分エディタを扱う。`activate` が実際のGit取得とVS Code表示を組み合わせる。

生成時のGitデータと表示時のテキストは境界DTOであり、ドメインの協調契約とは区別する。具象クラスへのキャストは不要。単一の生成関数と関数注入で足りるため、汎用DIコンテナや抽象ファクトリ階層は設けない。

## TypeScriptで守る範囲

- `unknown` を通信入口で検証し、画面要求とホスト通知を判別可能なunionへ変換する。
- 履歴を `empty / loading / error / ready` で表し、成功時だけコミット一覧、失敗時だけ説明を要求する。
- ファイルありの行履歴には行範囲を必須にし、差分要求にはパスを必須にする。
- 画面の通知処理は `never` による網羅性検査、状態別表示は `satisfies` で確認する。
- ラベルキーをリテラルunion、翻訳辞書を `Readonly<Record<...>>` として綴り間違いを検出する。
- 画面通知のトップレベルと一覧を `readonly` にする。深い実行時凍結を保証するものではない。
- Rebaseアクションは共通の型ガードで検証し、アサーションによる強制変換をなくす。
- 組み込みGit拡張のAPIは使用する外部契約を宣言し、`any` による伝播を防ぐ。

型は外部JSONを検証しないため、実行時パーサーも必要。パーサーは必須フィールドと値の条件を検証し、余分なフィールドを一律に拒否する厳密スキーマではない。翻訳辞書の `Object.fromEntries` のキー保持には、閉じたキー集合から生成する境界内のアサーションを残した。

## 契約の検証

正常系は追加・削除・名前変更・通常変更・初回コミットの内容取得先と表示をテストする。失敗系は取得失敗、実行前および取得中の世代変更をテストし、表示されないことを確認する。

通信テストは正常な往復と、不正なSHA・行範囲・状態・翻訳辞書・Rebase行を確認する。コンパイル専用テストは `@ts-expect-error` で不正な組み合わせを拒否し続けることを検証する。

## 今回保留したこと

Git解析全体のブランド型化、すべてのサービスのinterface化、履歴取得やCodeLensの全面再設計は行わない。具体的な次のユースケースで必要になった時点で境界を追加する。
